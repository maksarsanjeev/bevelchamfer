# Вылет при закрытии окон, 27 сентября 2026

## Установленные факты

- Пользователь закрывал окна bevelchamfer и insolyanka.
- BugSplat: SketchUp 2024 **24.0.484**, `Windows.Native`, время исключения **21:34:33 МСК**, файл дампа записан около 21:34:35. SketchUp запущен снова в 21:34:41.
- Минидамп содержит `EXCEPTION_ACCESS_VIOLATION` (`0xc0000005`): чтение адреса `0x13`, инструкция `SketchUp.exe+0x3c862a`.
- Инструкция читает `[rax+4]` при недействительном указателе. Последующий код этой же функции вызывает Qt `QWidget::frameGeometry`, затем ширину, высоту и координаты QRect. Это подтверждает связь упавшего нативного участка с геометрией окна. Сырые адреса на стеке не выдаются за полностью восстановленный стек вызовов.
- В нашем коде `ChamferPanel#set_on_closed` вызывал `ChamferPreview.stop`. Деактивация превью вызывала `preview_state(false)`, которая отправляла `execute_script` через оставшуюся ссылку на закрывающееся окно.
- insolyanka при закрытии обнуляет ссылку на окно; её отправка JavaScript уже проверяет `visible?`. Общий конфликт расширений не доказан.

## Что исправлено в 0.2.2

Закрывающееся окно помечается заранее. Его ссылка сбрасывается до остановки превью; JavaScript и отложенные action callbacks не выполняются для закрывающегося или устаревшего окна. Остановка инструмента вынесена из нативного обработчика закрытия в таймер. Обёртка HtmlDialog удерживается до завершения обработки закрытия Qt/CEF. Повторное открытие создаёт окно с заново привязанными callbacks.

Это устраняет обнаруженную ошибку жизненного цикла нашего окна. **Нельзя утверждать, что именно эта Ruby-цепочка вызвала исходное нативное исключение:** в дампе нет полного стека с Ruby callbacks и символов внутренних функций SketchUp. Не установлено также, какое из двух окон непосредственно инициировало сбой.

## Проверка

В настоящем SketchUp 2024 выполнены шесть последовательных циклов открытия обоих окон и закрытия в чередующемся порядке. Превью активно до закрытия; после закрытия выполняется сборка мусора. Проверены отсутствие отправки JavaScript закрытому окну, сброс ссылки, отключение превью и сохранность геометрии модели. Все шесть циклов прошли без вылета. После повторного открытия настоящие DOM-кнопки «Показать» и «Применить» запускают Ruby callbacks; превью оставляет исходник нетронутым, применение строит замкнутую параметрическую геометрию.

Сценарии: `test/dialog_close.rb`, затем `dialog_reopen.rb`, `dialog_reopen_click.rb`, `dialog_reopen_apply.rb`, `dialog_reopen_finish.rb`, через `tools/su.ps1`. Между запросами SketchUp обрабатывает события и таймеры. Для парного сценария нужен исходник insolyanka в соседнем репозитории либо путь в `BC_INSOLYANKA_ROOT`.

Дамп и копия журнала сохранены только локально в `build/crash-20260927`; они не публикуются. Успешные проверки снижают риск повторения, но не доказывают отсутствие всех нативных ошибок закрытия окон.

Семантика обработчиков сверена с [официальной документацией HtmlDialog](https://ruby.sketchup.com/UI/HtmlDialog.html#set_on_closed-instance_method): `set_on_closed` вызывается уже в процессе закрытия; закрытое окно теряет action callbacks.
